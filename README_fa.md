# راهنمای فارسی — اجرای بی‌سر سیگنال‌ها روی GitHub Actions (رایگان)

این بسته، موتور سیگنال اپ `vc69v5` را به‌صورت **بدون رابط گرافیکی** روی
GitHub Actions اجرا می‌کند و هر سیگنال جدید را به **تلگرام** می‌فرستد.
هیچ هزینه‌ای ندارد (ریپوی عمومی = دقیقه‌های Actions نامحدود).

## چه چیزی در بسته است

| فایل | نقش |
|---|---|
| `vc69v5_app.py` | اپ اصلی (همان نسخه‌ی دسکتاپ، با سه‌تایی جدید x/y/z) |
| `vc69v5_headless.py` | اجراکننده‌ی بی‌سر: هر بار اجرا = یک بازرسی |
| `.github/workflows/signals.yml` | زمان‌بند: هر ۱۵ دقیقه |
| `requirements.txt` | وابستگی‌ها (شامل wheel محلی tvDatafeed) |
| `tvdatafeed-2.1.0-py3-none-any.whl` | کتابخانه‌ی TradingView |
| `state/state.json` | حافظه‌ی «آخرین کندل بررسی‌شده» (بین اجراها commit می‌شود) |

## تنظیمات اعمال‌شده (طبق درخواست)

* چارت: **3m / 5m / 15m** — تایم‌فریم پایین: **1m**
* فاصله‌ی بازرسی: **هر ۱۵ دقیقه** (`*/15`) — چون ایران UTC+3:30 ثابت است،
  دقیقه‌های UTC یعنی :00/:15/:30/:45 دقیقاً روی ربع‌ساعت تهران می‌افتند
  (:30/:45/:00/:15 تهران).
* **اولین اجرا: 2026-11-08 ساعت 13:30 تهران** — قبل از آن هر اجرا فقط یک
  پیام «زمان اولین اجرا نرسیده» می‌نویسد و خارج می‌شود. (برای تغییر، مقدار
  `FIRST_RUN_TEHRAN` در `signals.yml` را عوض کنید.)
* فقط **BTC / PEPE / ZEC** — اسپات و فیوچرز از ccxt و تریدینگ‌ویو (XAU حذف است).
* در متن هر سیگنال، برای هر خانواده‌ی نماد سه‌عدد **x/y/z** درج می‌شود:
  `BTCUSDT 2/15/40` = دو صرافی تأیید کردند از ۱۵ صرافیِ بررسی‌شده، و حجم
  همین دو صرافی ۴۰٪ حجم کل آن ۱۵ صرافی است. خانواده‌ها:
  `BTCUSDT` (اسپات ccxt + اسپات TV)، `BTCUSDT.P` (فیوچرز ccxt + پرپ TV)،
  `BTCUSD` (بروکرهای CFD — فقط BTC). برای PEPE و ZEC خانواده‌ی CFD وجود ندارد.
* خط شمارش‌ها هم سه‌عددی است: `Spot: 1/12/8 | Futures: 5/13/38 | TV-Spot: … | TV-Perp: …`
  عدد سومِ هر گروه = درصد حجمِ صرافی‌های تأییدکننده از حجم کلِ همان گروه
  (اسپات، فیوچرز، اسپات TV و پرپ TV هرکدام جداگانه محاسبه می‌شوند).

## راه‌اندازی (۱۰ دقیقه)

1. در گیت‌هاب یک ریپوی **عمومی (Public)** جدید بسازید، مثلاً `vc69v5-bot`.
2. تمام محتویات همین پوشه را آپلود کنید (شامل پوشه‌ی مخفی `.github`).
   با خود سایت گیت‌هاب هم می‌شود: Upload files → کشیدن‌ورهاکردن همه‌ی فایل‌ها.
3. در `Settings → Secrets and variables → Actions` این Secret ها را بسازید:
   * `TG_TOKEN` — توکن بات تلگرام (از @BotFather بگیرید)
   * `TG_CHAT` — آیدی عددی چت خودتان (از @userinfobot بپرسید؛ اول به بات
     خودتان یک /start بدهید)
   * `TV_USER` و `TV_PASS` — **اختیاری ولی توصیه‌شده**: یک اکانت رایگان
     تریدینگ‌ویو؛ بدون آن داده‌ی TV ناشناس است و ممکن است گاهی 429 بدهد.
4. تب **Actions** را باز کنید و workflows را Enable کنید.
5. برای تست فوری، روی `vc69v5-signals → Run workflow` بزنید (اجرای دستی
   هم اگر قبل از 13:30 باشد فقط پیام «زمان نرسیده» می‌دهد).
6. از این به بعد هر ۱۵ دقیقه خودکار اجرا می‌شود.

## چطور کار می‌کند (و چون سیگنال از دست نمی‌رود)

* هر اجرا فایل `state/state.json` را می‌خواند، **همه‌ی کندل‌های چارتِ بسته‌شده
  از اجرای قبلی** را ارزیابی می‌کند و برای هر سیگنال جدید پیام می‌فرستد؛ بعد
  state را commit و push می‌کند. پس اگر گیت‌هاب اجرای یک ربع را چند دقیقه
  دیر شروع کند، هیچ کندلی از قلم نمی‌افتد و هیچ سیگنالی دوباره فرستاده
  نمی‌شود — زمان‌بندیِ سیگنال همیشه دقیقاً روی مرز کندل است.
* در اولین اجرا فقط کندل‌های بسته‌شده‌ی همان ربع آخر ارزیابی می‌شوند (پایه).
* اگر state بیشتر از ۶ ساعت عقب بماند (مثلاً Actions غیرفعال بوده)، فقط
  ۶ ساعت آخر بررسی می‌شود تا سیل پیام نیاید (`MAX_LOOKBACK_MIN`).

## نکته‌ها

* **تأخیر کرون گیت‌هاب**: آغاز اجرا گاهی چند دقیقه دیرتر از ربع‌ساعت است؛
  این تأثیری بر زمانِ سیگنال‌ها ندارد، فقط لحظه‌ی تحویل پیام را جابه‌جا می‌کند.
* برای توکن/چت تست، موقتاً در `signals.yml` مقادیر واقعی نگذارید — همیشه
  از Secrets استفاده کنید (ریپو عمومی است).
* اگر خواستید پارامترهای اندیکاتور را عوض کنید: `DIFFERENT`, `MIN_VOL`,
  `VOL_SMA_LEN`, `MIN_CONFIRM`, `MIN_EXCHANGES` در بخش `env` همان yml.
* `SHOW_GLOBAL: "1"` سیگنال‌های GLOBAL LONG/SHORT را هم فعال می‌کند.
* اجرای محلی (روی کامپیوتر خودتان، برای تست):
  `pip install -r requirements.txt` سپس `python vc69v5_headless.py --dry-run`
  (حالت dry-run فقط در لاگ چاپ می‌کند و به تلگرام نمی‌فرستد).
