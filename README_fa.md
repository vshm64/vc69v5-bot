# ربات VC69V5 روی GitHub Actions

## راه‌اندازی (یک بار)

1. **فایل‌ها را در ریپو بارگذاری کنید.** فایل زیپ را باز کنید و محتوای آن را در ریپو آپلود کنید (Add file → Upload files).
   - پوشه `.github` در ویندوز مخفی است. اگر آپلودش نشد: در GitHub روی Add file → Create new file بزنید، در کادر نام این مسیر را بنویسید و محتوای فایل `signals.yml` داخل زیپ را کپی کنید:
     `.github/workflows/signals.yml`
   - فایل قدیمی `signals.yml` که **در ریشه** ریپو است را حذف کنید. GitHub فقط فایل داخل `.github/workflows` را اجرا می‌کند و فایل ریشه فقط گیج‌کننده است.
   - فایل `tvdatafeed-2.1.0-py3-none-any.whl` را نگه دارید (فقط اگر TradingView را روشن کنید لازم می‌شود).
2. **Secrets:** Settings → Secrets and variables → Actions → New repository secret
   - `TG_TOKEN` = توکن ربات تلگرام
   - `TG_CHAT` = شناسه چت (قبل از آن به ربات یک پیام بدهید؛ برای گروه یا کانال ربات باید عضو/ادمین باشد)
3. **شروع:** تب Actions → `vc69v5-signals` → Run workflow (فقط یک بار). اجرای اول پیام تست را به تلگرام می‌فرستد.
4. بعد از آن، هر اجرا خودش اجرای بعدی را سر ربع ساعت (:00 / :15 / :30 / :45) شروع می‌کند.
   - توقف: Actions → `...` → Disable workflow.
   - اگر زنجیره قطع شد (مثلاً اجرای لغوشده): دوباره Run workflow بزنید.

## تنظیمات سیگنال: فقط `settings.toml`

فایل را در GitHub با آیکون مداد ویرایش کنید و Commit بزنید. اجرای بعدی (حداکثر ۱۵ دقیقه) آن را برمی‌دارد. هر ارز (`[BTC]` و `[PEPE]` و `[ZEC]`) جدا تنظیم می‌شود:

- `chart_timeframes` و `lower_timeframe`: تایم‌فریم‌ها و LTF هر ارز
- `spot` و `futures` و `cfd`: برای هر بازار `exchanges` (حداقل تعداد صرافی تأییدکننده) و `weight` (حداقل درصد وزن آن‌ها در همان بازار). `exchanges = 0` یعنی آن بازار خاموش.
- `total_weight`: حداقل درصد وزن همه منابع تأییدکننده نسبت به کل حجم همه بازارها. `0` یعنی خاموش.
- `different` و `min_volume` و `volume_sma_length`: ورودی‌های خود اندیکاتور

**قانون سیگنال:** حداقل یک بازار شرط خودش (تعداد + وزن) را داشته باشد **و** `total_weight` هم برقرار باشد.

اگر چیزی را اشتباه بنویسید (مثلاً حرف اشتباه در نام یک تنظیم)، ربات اجرا نمی‌شود و پیام خطا در تلگرام می‌آید.

### فرمت سیگنال

```
🟢 BUY  BTC/USDT  15m / 1m
Spot: 2/15/40/50
Futu: 3/12/55/50
```

در هر خط: `2/15/40/50` یعنی ۲ صرافی تأییدکننده / ۱۵ صرافی دارای داده در همان بازار / ۴۰٪ وزن آن‌ها در همان بازار / ۵۰٪ وزن همه منابع تأییدکننده در کل بازارها.

## تنظیم آستانه‌ها با لاگ

در لاگ هر اجرا (Actions → اجرا → Check for new signals) برای هر کندل بسته‌شده خطی مثل این هست، حتی وقتی سیگنال نیامده:

```
BTC 3m bar 2026-11-13 12:15 | 28 sources | BUY Spot 1/14/9 Futu 0/13/0 all 12% | SELL Spot 2/14/20 Futu 1/13/8 all 15%
```

اعداد `x/y/z` همان عددهای سیگنال‌اند. با دیدن آن‌ها می‌فهمید آستانه‌هایتان چقدر سخت یا آسان است و بر اساس آن `settings.toml` را تغییر دهید.

## TradingView

پیش‌فرض خاموش است، چون GitHub آی‌پی سرورهایش توسط TradingView بسته است و فقط اجرا را کند می‌کند. فقط اگر `enabled = true` کنید، پکیج‌ها نصب می‌شوند و CFD و TradingView اسپات/پرپ هم وارد می‌شوند.

## اگر سیگنال نیامد

لاگ آخرین اجرا را باز کنید:

- `Telegram NOT configured`: Secrets (`TG_TOKEN` و `TG_CHAT`) خالی یا اشتباه است.
- `Telegram HTTP 400/401/403`: توکن یا شناسه چت اشتباه است.
- `exchange(s) ready: ...`: اگر تعداد صرافی‌ها کم است، بقیه از آی‌پی GitHub بسته هستند (مثلاً BINANCE و BYBIT). به این صرافی‌ها نیازی نیست دست بزنید.
- خط‌های `CHECKED ...`: نشان می‌دهد هر ارز و تایم‌فریم چند کندل بررسی شد و چند سیگنال داد.
- اجرای قرمز: متن خطا در همان لاگ هست؛ آن را بفرستید.

## تغییرات این نسخه

- همه تنظیمات در `settings.toml`، جدا برای هر ارز.
- قانون تعداد/وزن برای هر بازار به‌علاوه وزن کل.
- پیام تست تلگرام در اولین اجرا.
- TradingView پیش‌فرض خاموش؛ سقف زمان برای هر مرحله و برای کل اجرا (جلوگیری از گیرکردن).
- state بعد از هر ارز ذخیره می‌شود و مرحله ذخیره حتی با خطا اجرا می‌شود.
- زمان‌بندی زنجیره طوری اصلاح شد که کندی یک اجرا آن را قطع نکند.
